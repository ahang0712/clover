# Operation_Analyzer

This tool analyzes read/write operations on global variables in C/C++ code, with a focus on access patterns to shared variables that may cause atomicity violations in concurrent contexts. It performs static analysis over LLVM IR and accurately identifies read/write operations in main and ISR functions.

## Features

- **LLVM IR analysis**: Analyze IR directly without parsing source code
- **Global variable detection**: Automatically detect all globals and their accesses
- **Function classification**: Distinguish main and ISR functions
- **Read/Write tracking**: Record each variable's load (read) and store (write) operations
- **Array index analysis**: Identify concrete indices of array accesses
- **MCP support**: Supports Multi-Call Protocol
- **Code annotation** ⭐ New: Add analysis results as inline comments to source code

## Usage

### CLI

#### 1) Basic analysis

```bash
# Use prebuilt llvm_api_demo tool
./llvm_api_demo <LLVM_IR_FILE> <OUTPUT_JSON_FILE>

# Example
./llvm_api_demo input.ll output.json
```

#### 2) Python wrapper

```bash
# Analyze a C file via Python wrapper
python analyzer.py <C_SOURCE_FILE> <OUTPUT_JSON_FILE>

# Example
python analyzer.py input.c output.json
```

#### 3) Code annotation ⭐ New

```bash
# Annotate source with read/write operations
python code_annotator.py <SOURCE_FILE> <ANALYSIS_JSON_FILE> [OUTPUT_FILE]

# Example
python code_annotator.py input.c input-output.json input_annotated.c
```

### MCP (Multi-Call Protocol)

Call from Python:

```python
from tool.Operation_Analyzer.analyzer import analyze_rw, annotate_code

# Analysis
result = analyze_rw(c_file_path, output_json_path)

# Annotation
annotation_result = annotate_code(source_file_path, analysis_json_path, annotated_output_path)

# Check result
if result['status'] == 'success':
    print("Analysis succeeded")
else:
    print(f"Analysis failed: {result.get('message', '')}")
```

## Input Format

Accepts LLVM IR generated by clang:

```bash
# Unoptimized IR

# Optimized IR
opt -O2 input.ll -S -o input-opt.ll
```

## Output Format

### 1) JSON analysis result

The JSON output includes the following fields:

```json
{
  "shared_variables": [
    {
      "name": "global_var",
      "type": "int",
      "is_array": false,
      "array_size": 0
    },
    {
      "name": "global_array",
      "type": "int[]",
      "is_array": true,
      "array_size": 10
    }
  ],
  "variable_accesses": [
    {
      "variable": "global_var",
      "function": "main",
      "type": "read",
      "line": 10,
      "array_index": null
    },
    {
      "variable": "global_array",
      "function": "isr_1",
      "type": "write",
      "line": 25,
      "array_index": "5"
    }
  ],
  "functions": {
    "main_functions": ["main", "svp_simple_001_001_main"],
    "isr_functions": ["isr_1", "svp_simple_001_001_isr_1", "svp_simple_001_001_isr_2"]
  }
}
```

#### Field descriptions

- **shared_variables**: List of all shared (global) variables
  - **name**: variable name
  - **type**: variable type
  - **is_array**: whether it is an array
  - **array_size**: size if it is an array

- **variable_accesses**: All variable access operations
  - **variable**: variable name
  - **function**: function performing the access
  - **type**: access type ("read" or "write")
  - **line**: source line (if debug info is available)
  - **array_index**: array index when applicable

- **functions**: Function classification
  - **main_functions**: list of main functions
  - **isr_functions**: list of ISR functions

### 2) Annotated source ⭐ New

The annotator adds inline comments to show read/write operations:

```c
void main() {
    init();
    
    global_var = 0;  // Write 'global_var' in Main
    
    for (i = 0; i < MAX; i++) {  // Operations: Read 'i' in Main; Write 'i' in Main
        array[global_var] = i;  // Operations: Read 'global_var' in Main; Write 'array[var]' in Main
    }
}

void isr_1() {
    global_var = TRIGGER;  // Write 'global_var' in ISR
}
```

## Integration with PlanAgent

This tool is integrated with PlanAgent and can be invoked via MCP. PlanAgent automates IR generation and analysis and adds results to facts. The new annotator can also generate source code with inline operation comments.

## Implementation Details

Core analysis is implemented in C++ using LLVM APIs to extract:

1. Global variable declarations/definitions
2. Function definitions and call relationships
3. Load/Store instructions, operands, and targets
4. GetElementPtr-based array index computations
5. Function name analysis (to identify main/ISR)

The Python wrapper (`analyzer.py`) provides MCP interfaces for integration. The new code annotator (`code_annotator.py`) adds inline comments to source code based on the analysis results.
